    PyVELM¶

    Odoo's semantics. Laravel's ergonomics. Filament's craft — in a Tailwind-native ERP shell that exists only here.

    PyVELM is a declarative Python ERP framework. Models, Odoo-style recordsets and modules, view inheritance via dict-op patches, and admin UX patterns familiar from Laravel and Filament—on a bespoke Tailwind + HTMX interface with its own layout and widgets. Built on a portable SQLAlchemy Core database layer (PostgreSQL or SQLite), FastAPI, and Jinja2.

    Latest release: v1.0.0 — SQLAlchemy database layer, SQLite portability, Laravel-style seeders, declarative Schema migrations. Docs are versioned (use the header picker for older lines).

    pip install pyvelm==1.0.0

    Published on PyPI.
    Maintained by Sam Maosa alongside Filament modules, flatpickr, nested-comments, and other packages — sponsor on GitHub (one profile, all projects).

    Quick start¶

    From PyPI (scaffold a new app):

    pipx install pyvelm
pyvelm init my_erp
cd my_erp
cp .env.example .env
docker compose up --build   # → http://localhost:8000/login  (admin / admin)

    From source (this repo):

    git clone https://github.com/coolsam726/pyvelm.git
cd pyvelm
cp .env.example .env       # set PYVELM_DSN
pip install -e .
docker compose up --build

    The bundled demo seeds partners, CRM leads, tags, sales users, and workflow records so the UI is populated on first boot. See Getting started for a guided walkthrough.

    Optional checks (repo examples, same module roots as examples/serve.py):

    python examples/basic.py
python examples/vellum_smoke.py

    Read in this order¶

    If you're new, read these in order:

    1. Getting started — boot the stack (Postgres, Docker, or SQLite), add your first module.
    2. Database layer (v1.0) — DSNs, dialects, SQLite vs Postgres, routing preview.
    3. Declaring models — fields, relationships, computed values, model inheritance, dotted search domains.
    4. Vellum — optional Eloquent-style queries and ergonomics (env.query, scopes, soft deletes).
    5. Building UIs — list, form, and kanban views; widgets; list domain; the search bar; row reorder.
    6. Form UX — notebooks, sticky actions, Ctrl+S, save toasts, opening related records in PvDialog.
    7. One2many on parent forms — embedded sub-grids: list_view, columns, form_view, edit_toggle, dialog vs inline.
    8. Extending views — patch views from another module without forking them.
    9. Modules — the manifest, data files, seeders, the loader, writing migrations, the Apps catalog.
    10. Report Builder — user-defined reports, visual builder, secure SQL compilation, export and scheduling.

    Then as you need them:

    • Navigation — shell menu layouts (apps vs sidebar), per-company override, depth, PYVELM_MENU_LAYOUT.
    • Document layouts — company PDF header/footer, layout designer, register_document, print routes.
    • Security — groups, ACL, record rules, multi-company scoping, the login flow.
    • Deployment — Docker, gunicorn, the background cron worker, sending email, CSRF / rate-limit / password-change.
    • Console commands — pyvelm make:module, make:model, db autogen, and related generators.
    • IDE typing stubs — pyvelm make:stubs, Pyright/Pylance, pyrightconfig.json auto-setup.
    • Architecture — design decisions behind the API (cache, domains, deferred items).

    The API reference is auto-generated from docstrings if you want the per-class details.

    What ships in the wheel¶

    The pyvelm package bundles modules under pyvelm/modules/ so a fresh install produces a bootable app:

    • base — ir.ui.view, res.users, res.groups, ir.model.access, ir.rule, ir.actions.server, base.automation, ir.cron, mail.message, res.country, res.region, res.company, ir.ui.menu. Plus the install hook that seeds the admin group + uid=1 superuser + ACL defaults + the mail-dispatcher cron.
    • admin — list / form views + sidebar menus that put a working management UI in front of the base models.
    • reports — ir.report / ir.report.run, visual builder, secure compiler, Excel/CSV/PDF export (see Report Builder).
    • console — Artisan-style pyvelm make:* generators (see Console commands).
    • vellum — marker module; import pyvelm.vellum in your models for the optional query-builder veneer (see Vellum).

    Apps prepend pyvelm.BUILTIN_MODULE_ROOTS to their own discovery roots:

    from pyvelm import BUILTIN_MODULE_ROOTS, loader

loader.load_and_install(
    BUILTIN_MODULE_ROOTS + [my_addons_dir],
    env,
)

    The illustrative addons (partners, partners_pro, crm, demo, vellum_demo) live under examples/ in the repo and are opt-in — they show patterns rather than being required.

    CLI¶

    pyvelm init my_erp              # scaffold a project
pyvelm make:module inventory     # empty module shell
pyvelm make:stubs                # IDE literals + pyrightconfig.json (optional)
pyvelm db autogen my_module      # write migration file from models
pyvelm db migrate               # upgrade installed modules (deploy)
pyvelm db migrate --all         # install/upgrade every discovered module
pyvelm db status                # installed vs manifest versions
pyvelm-cron --interval 60        # background cron + mail dispatcher

    See CLI reference, Console commands, IDE typing stubs, and Deployment → Background cron runner.
